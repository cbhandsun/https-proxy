# 2026-08-31 管理凭据启动竞态修复

## 问题与修复

并发启动的两个进程可能同时通过已有实例检查。旧实现会在占有管理端口之前写入管理凭据，因此随后因端口冲突退出的进程仍可能覆盖运行中进程的凭据文件，导致管理界面读取配置得到 401，并误显示为未配置。

- 只有成功绑定管理端口的进程可以发布管理凭据；凭据写入失败时拒绝启动。
- 管理端口和所有模型入口均已监听后才报告启动就绪。
- 仅有 HTTP 入口时不生成无用的 TLS 证书。
- 配置读取失败时明确显示错误，并阻止保存占位配置。
- 保留原有端口清理、管理鉴权、入口鉴权和 TLS 验证。
- 运行依赖 `ip-address` 更新至兼容范围内的 10.7.0，清除已检测到的生产依赖漏洞。

新增回归测试已接入统一单元及前端测试入口，覆盖并发绑定、失败进程不覆盖凭据、重启轮换凭据、错误凭据拒绝、凭据写入失败和配置读取失败后禁止写回。入口鉴权集成测试使用隔离目录、动态端口和预先加密的测试凭据，原有超时阈值及安全断言未放宽。
